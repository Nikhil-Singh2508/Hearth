# Deployment notes

## Vercel deployment

Deploy the frontend and API as two Vercel projects. The frontend's Vercel rewrite proxies `/api/*` to the backend, so the browser uses one origin and the existing secure session cookies continue to work.

1. Create and configure the Supabase project first. The backend requires Supabase PostgreSQL and private Storage; Vercel's local filesystem is temporary. Follow [Supabase setup](supabase-setup.md), and migrate any local data before switching users over.
2. Import this repository as a Vercel project named for the API. Set **Root Directory** to `backend`. Vercel detects the FastAPI app in `app/main.py` and installs its runtime dependencies from `pyproject.toml` (also listed in `requirements.txt`). Set production environment variables: `DATABASE_URL` (Supabase session pooler URI using `postgresql+psycopg`, `sslmode=require`), `APP_ENV=production`, `COOKIE_SECURE=true`, `CORS_ORIGINS=["https://YOUR-FRONTEND-PROJECT.vercel.app"]`, `PRIVATE_STORAGE_BACKEND=supabase`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, and `SUPABASE_STORAGE_BUCKET=hearth-private`. Add notification provider secrets only if you have configured those providers. Set the Vercel Function region near the Supabase database region.
3. Run Alembic against Supabase once before serving traffic: from a machine with the backend dependencies installed and the production `DATABASE_URL` set, run `alembic upgrade head` from `backend`. Bootstrap the initial owner on that database with `python -m app.bootstrap_owner`. Do not bootstrap if you imported an existing owner account.
4. Import the repository a second time as the frontend project. Set **Root Directory** to `frontend`, framework preset to Vite, build command to `npm run build`, and output directory to `dist`. In `frontend/vercel.json`, replace `YOUR-BACKEND-PROJECT` with the deployed API project's Vercel hostname, then deploy the frontend. Leave `VITE_API_URL` unset so the production frontend uses the same-origin `/api` rewrite; local development keeps using `http://localhost:8000`.
5. Set `CORS_ORIGINS` on the backend to the frontend's production origin and redeploy the backend. If using a custom domain, add it to that list and to the frontend project's domains. Verify login/logout, tenant and owner workflows, receipt downloads, document/evidence upload and download, and `/health/ready` before inviting tenants.

Vercel Functions limit request and response bodies to 4.5 MB, so document/evidence uploads larger than that will fail even though the app's bucket allows larger files. Keep uploads below 4.5 MB or move those uploads to a direct-to-Supabase signed upload flow. See Vercel's [server upload limits](https://vercel.com/docs/vercel-blob/server-upload). The app currently has no background worker; do not rely on Vercel requests for long-running jobs. Keep the Storage bucket private and use the server-only Supabase secret key. Review the [production security checklist](security-checklist.md) before storing real tenant or financial data.

The included Compose file provisions PostgreSQL for local development. The backend Dockerfile is a development foundation, not the Vercel deployment path. Do not expose tenant documents through a public URL or web directory. See [Supabase setup](supabase-setup.md).
